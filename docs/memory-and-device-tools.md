# 内存工具与设备扩展

实现日期：2026-10-19，开发基线 `51099af`。功能已接入，桌面操作与真实硬件均**待维护者验收**。用户本轮选择下次进行桌面验收，现有 Debug 实例和用户配置保持原样。

## 启用与范围

所有新增实验默认关闭。在“实验性功能”启用内存工具；设备扩展位于“新音频控制”下，别名/收藏排序、快捷键和蓝牙电量可分别启停。关闭实验保留配置，并停止对应采样、注册或读取循环。

详细配置位于应用页现有诊断区和交互页现有音频设备区，不增加任务栏组件或独立常驻监控窗口。新增设置登记为 `unreleased`，缺字段保持原行为；不调整 schema，重置沿用用户默认快照。

本次没有自动系统清理、全进程工作集清理、蓝牙配对/连接/断开、厂商 HID 电量、前台应用切换快捷键，也没有增加运行时联网或遥测。功能设计参考[调研报告](experimental-feature-research.md)，平台读取及状态管理独立实现，未引入上游代码或二进制。

## 内存工具

### 自身采样与回收

启用后，应用页诊断区显示 AF 工作集、私有提交、托管堆、句柄与线程数，以及系统可用物理内存和采样时间。页面可见时每两秒后台采样，离开后取消；失败显示不可用。不同内存指标存在交叠，不能相加。

温和回收沿用现有托管回收，深度回收沿用压缩 GC 与当前进程工作集交还。旧手动按钮和新按钮共用 `MemoryPruneCoordinator` 的异步执行管线、节流与重入保护；已有自动剪枝策略保持原样。进程采样使用新的 `Process` 快照，避免属性缓存使前后读数失真。

结果包含强度、执行状态、工作集/私有提交/托管堆前后读数、耗时及工作集操作结果。忙碌时不重复提交。页面关闭或停用后不呈现迟到结果；已经开始的 GC 不伪装成已取消。工作集下降不代表活对象提交减少或泄漏已修复，也不承诺播放或交互性能改善。

### 手动系统操作

系统清理另有默认关闭的子开关，唯一项目是低优先级待机页。用户点击后通过当前 `AFMediaBar.exe` 请求 UAC；主进程保持原权限，不创建常驻提权服务、计划任务或额外安装组件。

同一程序使用固定参数 `--internal-memory-clean-low-standby` 进入一次性辅助模式。参数必须完全匹配且只有一项；无效内部请求返回 14，不进入普通应用。辅助分支位于单实例与普通服务初始化之前，Host 延迟创建，辅助退出跳过设置保存和普通服务收尾。

执行端只启用所需令牌权限，以 `NtSetSystemInformation` 的 `SystemMemoryListInformation` / `MemoryPurgeLowPriorityStandbyList` 发起操作。权限不足、接口缺失或不支持时明确失败，不回退为全待机页、全进程或其他清理。该信息类没有完整公开稳定契约，效果及可用性取决于 Windows 版本。

辅助进程有 30 秒退出看门狗，主进程在启动后最多异步等候 35 秒。UAC 等待由用户处理；操作提交后不承诺可中断。超时表示结果未确认，不自动重试。返回协议区分成功、权限不足、不支持、失败、超时、无效请求、取消和忙碌。

主进程在操作前后读取系统可用内存。读数包含其他程序同期活动，不能作为本次精确释放量；缓存重建也可能增加后续 I/O 或缺页。

## 设备个性化与快捷键

### 别名、收藏和顺序

输入与输出分别保存偏好，键由方向和稳定端点标识组成。别名只影响 AF 展示，不重命名 Windows 设备。收藏置顶，组内按用户顺序排列；未收藏设备仍可访问，新设备追加。设置页通过上移/下移调整顺序，选择入口统一使用设备目录生成的显示结果。

失联条目保留别名、收藏、顺序和快捷键。可以删除配置，或明确选择同方向的活动端点重新关联；重新关联会替换目标端点的 AF 偏好及允许状态。名称相同不能证明身份相同，重新配对不会按名称自动继承配置。

### 快捷键

每个端点可配置直达组合键，输入和输出各有一个收藏循环键。组合键默认为空；示例为 `Ctrl+Alt+F8`，需包含 Ctrl 或 Alt，不接受 Win、F12 和纯修饰键。无效、内部重复、被其他程序占用或系统拒绝的状态均在设置中显示。

应用级服务按需创建消息窗口，通过 `RegisterHotKey` / `WM_HOTKEY` 接收输入，不安装键盘 Hook，并禁止按住自动连发。配置变化先注销旧注册；停用后释放消息窗口，关闭设置窗口不注销仍启用的快捷键。

直达和循环均复用 `AudioDeviceSwitchCoordinator`，只切换系统默认设备，并遵循已有黑名单和通信角色配置。收藏循环按保存顺序跳过离线/隐藏端点；没有候选保持原设备，一个候选直接选中。快速输入合并候选步数，代际和取消令牌阻止旧请求覆盖新目标。成功沿用音频切换反馈，不新增系统通知。

个性化关闭后，已有收藏仍可供已启用的循环键使用；重新编辑收藏需开启个性化。所有端点身份和切换逻辑均不依赖别名或电量文字。

## 蓝牙电量与通知

音频端点读取自己的设备容器标识；蓝牙侧批量读取 PnP 容器、设备地址与 Windows 电量属性，再与配对设备的系统身份关联。只有明确容器或地址关联才合并，不按显示名称猜测。同一物理耳机的输入/输出共享电量快照。

首版读取 Windows 驱动提供的电量属性；关联设备处于已连接状态且没有该读数时，尝试标准 BLE Battery Service。Windows 属性可能缺失、类型不符或不更新；经典蓝牙耳机也未必提供 BLE 服务。因此这是通用接口支持，**没有经过任何具体耳机型号验收，不等于所有耳机可用**。无法可靠关联的端点不附加猜测电量；已识别但无读数的蓝牙设备显示未知。

设备菜单展示电量；当前设备提示及设置行展示来源、最后有效时间和是否实时。失败保留最后有效读数但标为非实时，不用 0% 代替错误。断开或超过三分钟的旧数据不能作为实时通知依据。

实验开启时由应用级服务拥有读取循环，通过已有设备事件唤醒并检查相关音频端点，正常补充读取间隔至少一分钟。每批 PnP 只枚举一次，GATT 单项等待最多五秒，批次有二十秒取消期限；查询共用单次在途门闩，失败退避最高十分钟。停用、退出及代际变化阻止迟到快照与通知；读取中创建的原生信息集、蓝牙设备和 GATT 服务在各自读取边界释放。

低电量提醒默认关闭，只针对当前系统输出耳机，默认 20%，可设 5%–90%。启动、启用提醒、切换耳机、重连或读取失败后的恢复先建立基线，不因已有低电量立即弹窗。后续有效读数降到阈值才提醒一次；达到阈值以上五个百分点后重新允许提醒。状态按物理设备保存于本次运行内，菜单刷新和临时切换不会重置已提醒状态，不持久化提醒历史。
