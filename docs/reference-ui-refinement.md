## 内存入口的区别与整理

| 操作 | 实际范围和行为 |
|---|---|
| 温和回收 | 仅 AF；尝试回收不再使用的托管对象，不主动交还工作集 |
| 深度回收 | 仅 AF；强制压缩 GC，随后尝试交还当前进程工作集 |
| 原“立即压缩” | 与深度回收是同一个命令，并非第三种清理强度 |
| 清理低优先级待机页 | Windows 系统缓存；需要提权，不属于 AF 自身回收 |

Mem Reduct 将指标、执行入口和清理区域设置分开。AF 借鉴这一组织方式，新增应用页独立“内存工具”分组：温和、深度各有说明，内存指标默认折叠，最近回收结果单独展示，系统缓存清理使用独立展开卡。

内存实验开启时隐藏原“立即压缩”行，只保留温和/深度两个入口；实验关闭时保留原入口。这样保留未开启实验时的既有用法，同时避免把同一操作展示成两种能力。实验页跳转和设置搜索同步指向新分组。

没有引入自动清理、全进程清理或额外系统清理项目。工作集下降仍不等于提交量下降，也不代表泄漏已修复；详见[实施说明](memory-and-device-tools.md)。

## 设备与快捷键设置

PeriTray 的设备列表以简洁状态和常用开关为主，快捷键有专门的录制流程。AF 改为每台设备默认展示名称、状态、收藏和允许切换；别名、快捷键、顺序及电量详情放入默认收起的编辑区。

快捷键不再要求手写组合键。点击录制框后按键；Esc 取消，退格/Delete 清除，Tab 离开。录制期间暂停 AF 自身的全局注册，避免现有组合键被 AF 消耗；失焦、控件卸载及页面作用域释放时归还暂停租约。外部程序占用的组合键仍由注册结果反馈，不引入键盘 Hook。

设备刷新改为按端点复用行实例并移动列表项，不再整体清空、重建。电量刷新、收藏切换或别名保存因此不会主动重建仍然存在的编辑行；活动/失联分组变化仍按最新设备状态同步。

## 虚拟声卡的电量误关联

PeriTray 明确把全零及 `00000000-0000-0000-ffff-ffffffffffff` 视为占位容器。后者可能由不相关的软件设备共享，不能证明设备属于同一物理外设。AF 原实现只排除了全零值，存在把共享占位容器关联到蓝牙信息的路径。

现在在音频端点读取、蓝牙关联和缓存查询边界统一排除这两种占位值。不能可靠关联时不附加电量。已识别的蓝牙设备若没有有效读数，只显示一次“暂时无法获取电量”，不再连续展示电量、时间和来源三个“未知”。

这修复了可导致截图现象的身份判断缺口；未读取截图中虚拟声卡的实际容器值，不能据此认定它是该设备现象的唯一原因。真实端点仍待维护者验收。
