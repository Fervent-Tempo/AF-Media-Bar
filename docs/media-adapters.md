# 媒体适配器接入规则

适用于新增播放器适配、修改来源身份和双通道仲裁，以及移动媒体实现。功能与兼容性方案的讨论要求见 [CONTRIBUTING.md](../CONTRIBUTING.md)；本页规定实现接入方式。

## 按所有权放置实现

| 位置（相对 `src/AFMediaBar/Classes/`） | 职责 |
| --- | --- |
| `Services/Media/` | 通用来源目录、选择、过滤、激活与协调；协调者可调用 SMTC 通道实现 |
| `Services/Media/Smtc/` | SMTC 会话目录、有效性检查、快照转换、重连策略及目录资源租约 |
| `Services/Media/Readers/` | 共享的进程身份、PE 构建指纹、只读模式扫描与读取诊断；不持有具体播放器布局 |
| `Services/Media/Sources/Shared/` | 跨来源共享的 SMTC 优先合并状态、短暂失败缓冲和读取日志入口 |
| `Services/Media/Sources/<来源>/` | 一个播放器的 Provider、身份和合并策略、内存读取器、构建表、私有元数据解析、连续性处理 |
| `Abstractions/` | 跨实现共享的 Provider 与策略契约；独立公开契约按类型名建文件 |
| `Models/` | 跨模块传递的快照和候选数据 |
| `Services/Lyrics/` | 歌词提供器与获取流程，即使与媒体来源同属一个播放器也由此处负责 |

SMTC 是多个播放器共享的系统通道，与 `Sources/` 并列。来源专属代码集中在对应来源目录，不再拆到 `Services/Players/`。新目录的命名空间使用 `AFMediaBar.Classes.Services.Media.Smtc` 或 `AFMediaBar.Classes.Services.Media.Sources.<来源>`。

## 读取层与合并层

- 读取层按来源保留自己的进程/模块定位、构建指纹、特征码和字段校验；共享基础设施只放进程身份、PE 构建指纹、只读模式扫描、短暂失败缓冲和诊断。不要为了统一而强行让两个播放器共用同一种偏移或注入方式。
- 合并层统一为 SMTC 优先：标题、歌手、封面、播放状态和控制来自 SMTC；位置、时长和来源歌词由内存补充。内存不可用或 stale 时回退 SMTC；没有 SMTC 时回退内存。
- 内存曲目与 SMTC 不一致时，先保留 1.5 秒给 SMTC 追上；这段时间只显示 SMTC，不叠加内存时间轴或歌词。超时后仍不一致时，继续使用 SMTC 元数据，但时间轴/歌词改由内存提供。不按标题后缀做归一化。
- 封面始终取 SMTC，不再按内存与 SMTC 的标题/歌手是否一致来决定是否继承。换歌缓冲只保护进度和歌词，不阻止封面更新。
- 未知酷狗构建、网易云特征码非唯一命中、进程权限拒绝、短读或双读不一致都必须失败关闭；不发布猜测的进度或封面。诊断记录来源、PID、构建指纹、匹配到的构建/模式、失败阶段和原因，不记录原始内存内容。

`MediaSnapshotBuilder` 位于 `Smtc/`，因为它以 SMTC 会话为输入，并持有该通道的补全缓存；歌词获取委托给 `LyricsService`。未来需要跨通道共享补全时，先确认实际复用和缓存所有权，再提取共用实现。

SMTC、在线兜底及独立来源的自动取词均遵守失败冷却与重试上限：暂停时允许首次加载，失败后仅在播放中自动重试，沿用 30 秒失败缓存；同一曲目连续失败最多 10 轮（含首次），每轮包含当次取词链的全部歌词来源。失败计数独立于结果缓存，暂停切换、缓存过期和内存剪枝不重置计数；取词相关设置变化时清空。各缓存所有者按现有曲目身份保留最近 64 条计数，不写入设置或磁盘，重启应用后重置。

## 接入步骤

1. **选择能力。** 只增强当前 SMTC 快照时实现 `IMediaSourceProvider`；需要没有 SMTC 时仍可被选择时，实现 `IIndependentMediaSourceProvider`，参考网易云和酷狗。Provider 负责轮询、读取器、取消和释放，纯策略不持有外部资源。自行取词的提供器声明 `ProvidesLyrics`，SMTC 构建器通过目录跳过重复取词；提供器明确报告不可用时仍走现有兜底。
2. **定义身份与仲裁。** 独立来源提供稳定的 `SourcePolicy`。`SourceId` 和 `SelectionKey` 在注册来源间唯一，既有值保持兼容；`Matches` 同时识别规范 ID 和别名，别名互不重叠。`CanHandle` 与策略使用一致的来源识别规则。
3. **组合候选与快照。** `Combine` 保留其他来源候选及相对顺序，只合并自己的通道；无 SMTC 时允许 `SessionKey` 为空，通道到达、消失、重建时维持稳定选择键。`Merge` 使用共享的 SMTC 优先策略：SMTC 提供元数据、封面、播放状态和控制；内存只在可用、非 stale 且通过换歌缓冲后补充位置、时长和歌词。内存不可用或 stale 时回退 SMTC；无 SMTC 时回退内存。
4. **注册。** 在 `App.xaml.cs` 注册 Provider，并以 `IMediaSourceProvider` 解析同一个实例；需要内存剪枝时，`IMemoryPrunable` 也绑定该实例。`MediaSourceRegistry` 从 Provider 自动发现独立能力，无需第二份来源名单。资源启动、事件订阅与释放沿用现有协调流程，目录不接管 Provider 生命周期。
5. **接通设置。** 通用管线和设置页通过目录归一化来源，过滤使用同一身份规则。检测到会话、独立快照或正在运行的独立播放器时列出来源。已配置的允许项和首选项离线时仍可编辑。Provider 内部判断是否允许读取时，可给 `MediaSourceFilterPolicy` 传入自身的归一化规则。新适配器不要求在协调者、过滤器或 ViewModel 中新增播放器分支。
6. **验证。** 除本来源读取测试外，通过目录验证无 SMTC 候选、别名过滤、双通道去重、失效回退和与另一来源共存；验证普通刷新保留手动选择，新会话和播放活动按已配置策略仲裁。读取器还要覆盖构建指纹/特征码非唯一命中、权限拒绝、双读不一致、stale 回退和最新目标版本；合并策略覆盖 SMTC 优先、1.5 秒换歌缓冲、无 SMTC 与内存不可用。覆盖取消后晚到结果、重复停止及释放等受影响的资源路径，再按贡献指南串行构建和测试，并运行架构检查。

## 完成条件

- 来源专属实现均归入自己的目录，通用管线和设置页没有新增具体适配器依赖。
- 注册后能通过现有目录参与发现、选择、过滤和解析，SMTC 增强器不必实现独立来源能力。
- 保持原有来源 ID、选择键、设置格式与失败回退语义；若要改变，单独说明兼容性方案。
- 构建、测试和架构检查结果如实记录；真实播放器切换、退出与资源清理未验证时标为“待维护者验收”。
