# 竖向任务栏

竖向任务栏为正式功能。在选中的真实左侧或右侧系统任务栏上自动竖向显示，无需实验开关；不会修改系统任务栏的位置。目标显示器仍在“显示与位置”选择，横向与竖向共享同一份配置。

## 呈现与配置

横竖任务栏共享既有任务栏配置，在现有页面编辑，不复制设置。主轴对应纵轴，Start／Center／End 对应上／中／下；组件顺序、显隐、固定或跟随长度、空间预算、拖动及取消约束复用现有策略。实际宽度来自目标任务栏和 DPI，文字字号不随厚度整体缩小。

标题、歌手和歌词共用同一个 WebView2。原生竖排保留原文、中文直立、连续西文侧转；主文字 18 DIP、副信息 14 DIP，现有字号百分比只应用一次，文字列组在宽度内居中。真实逐字进度沿文字推进方向擦亮，普通行级歌词不伪造逐字进度。Web 初始化或恢复失败时保留未旋转的简化 WPF 元数据，完整文字在完整面板查看。

性能指标保持正向横排小卡片，采样不改变组件的保留尺寸；频谱聚合显示频段，采样数量和计算不变。快捷控制复用原按钮和命令，以独立不透明 Popup 向屏幕内侧展开成竖列。封面和完整面板同样向内展开，菜单、提示和完整面板保持横排。

## 生命周期与验证

宿主、Popup 和 WebView2 分别由窗口、媒体控件及渲染器持有；隐藏、卸载、方向变化、Explorer 恢复和退出关闭旧呈现、停止计时器并使旧回调失效。同锚点内容长度变化保留弹层，真实位置或环境变化继续执行原交互保护。

纯策略与实际 WPF 控件回归覆盖混排度量、Emoji 字素、频段聚合、实际宽度和字号、指标稳定尺寸及方向切换。基于实际网页源码的截图用于检查文字方向和居中，不能证明任务栏 HWND、层级和输入行为。

真实左右任务栏、混合 DPI、多屏、封面层级、鼠标跨弹层、自动隐藏、Explorer 重启和退出清理均待维护者验收。

自动收起副信息及窄栏提示尚未在本批实现；桌面悬浮完成后再统一适配横竖小任务栏，作为正式功能。

窄任务栏的文字密度规则与横向共用，见[小任务栏自适应](small-taskbar.md)。该规则不修改保存的显隐偏好。
