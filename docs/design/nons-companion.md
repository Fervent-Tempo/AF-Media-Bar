# Nons 播放队列联动

修改 AF 的 Nons 队列入口、队列浮层、随机按钮或播放器 companion 能力时读本文。

## 目的与边界

Nons 继续负责曲库、账号、真实播放队列、播放调度和音频资源；AF 只读取稳定的本机快照、提交少量意图并呈现结果。AF 不保存 Nons 登录凭据，不另建播放引擎，也不从正在浏览的页面推断队列来源。

当前 Nons 1.12.4 的桌面开放 API 提供播放状态、只读队列、跳转/随机/循环等控制、歌词、封面和 WebSocket 事件。它**没有**歌单读取、收藏、队列删除/插播、页面导航、账号上下文、分页、`requestId` 或队列条目 ID。因此 AF 不提供这些尚未具备真实后端的按钮或菜单，也不读取 Nons 数据库或使用 UI 自动化。

## 实际契约

| 能力 | 数据/行为 | AF 的用法 |
|---|---|---|
| 能力发现 | `GET /v1/health`：版本、协议版本、能力列表 | 要求协议 1 和播放/队列/事件能力；缺少控制能力时只读 |
| 状态 | `GET /v1/player`：状态、当前索引、当前歌曲、随机/循环、队列版本 | 当前项、随机按钮、待确认状态 |
| 队列 | `GET /v1/queue`：`items`、`shuffleOrder`、队列版本 | 按 `items` 原顺序展示；不按随机顺序重排 |
| 跳转 | `POST /v1/player/commands`：`jump { queueRevision, trackId }` | 队列歌曲单击 |
| 随机 | `POST /v1/player/commands`：`shuffle { queueRevision, shuffle }` | 完整面板按下目标状态设置，不做“切换”重试 |
| 事件 | `WS /v1/events`：初始快照、队列、状态、进度、`events.lagged` | 增量更新；明确失步或断开时重新取完整快照 |

命令成功返回 `202 {"accepted":true}`，只表示播放核心已接收。AF 必须等待后续状态或事件确认实际变化；不能仅凭 202 显示“播放成功”。`queueRevision` 在队列或随机顺序变化时递增；跳转和随机都携带它。`sequence` 是发布批次，序号缺口不代表数据丢失；只在 `events.lagged`、连接关闭或队列版本冲突时重新同步。

## 队列与版本

- 队列展示顺序就是 `/v1/queue.items` 的顺序；当前项由 `/v1/player.index` 指向同版本队列。`shuffleOrder` 只表示 Nons 的随机顺序，不参与本地重排，AF 不计算下一首。
- 队列浮层打开时把当前项放在视口中间，行单击播放；当前项同时作为选中项，因此重新打开后选中/播放标记仍成立。列表固定显示五行，鼠标中键回到当前项；行选中反馈与设备弹窗共用强调色底和左侧标记。列表只为可见行请求本机低清封面，失败保留主题占位图；不显示当前歌曲摘要、底部计数或关闭按钮。
- 驻留层队列入口默认关闭，悬浮控制层默认开启；两处入口都只在 AFMB 当前显示的媒体来源属于受支持 companion（目前为 Nons）时出现。仅连接过 companion、但当前来源已切到其他播放器时，入口隐藏。
- 封面缩略图按需加载，解码为 32px，使用有界 LRU（最多 96 张）；行被虚拟化卸载时释放该行引用，迟到结果不回填，缓存命中后滚动回来可立即显示。
- Nons 队列去重，`trackId` 能确定队列中的歌曲；跳转使用它而不是界面行号。若未来允许同曲重复，需要 Nons 先提供队列条目 ID。
- 版本已过期时先刷新；目标歌曲仍存在才用新版本重试一次，已删除则明确返回“歌曲已不在队列”，不跳到其他歌曲。
- 收到“已接收”后进入待确认：跳转等待当前歌曲匹配，随机等待目标布尔值；超时刷新一次仍不一致时显示“已提交，等待播放器更新”，不显示成功。
- 面板关闭时取消等待；旧连接、旧代次和已关闭窗口的结果不得写回界面。

## 连接与失败

连接按需建立：打开队列浮层或在完整面板中确认当前来源属于 Nons 时才开始，首次使用才联网。连接成功后复用；断开时做有限次自动重连，失败进入可手动重试状态。Nons 重启没有实例 ID，AF 以新连接代次和完整快照替换旧状态，不跨连接比较队列版本。

| 场景 | 行为 |
|---|---|
| Nons 未运行、开放 API 未启用或端口变化 | 面板显示原因和重试；不后台无限轮询，不伪造队列 |
| 协议版本或能力不兼容 | 不读取队列、不发送命令，显示版本/接口提示 |
| 空队列或当前索引为空 | 显示空状态，不虚构当前歌曲 |
| 队列版本变化、请求返回 stale queue | 刷新快照；同一目标仍存在时最多重试一次 |
| WebSocket 断开、`events.lagged` 或 Nons 重启 | 作废旧状态，重新取完整快照；重连期间禁用跳转/随机 |
| 慢消费者或大队列 | 完整接收并限制单条消息大小；列表虚拟化，不静默截断 |
| 当前播放器切换到其他来源 | 驻留层和悬停层的队列入口都隐藏；完整面板随机按钮隐藏；已打开的队列浮层仍明确标注 Nons |
| 高对比度、关闭动画、DPI、多屏 | 走既有主题、动效和窗口定位策略；真实桌面场景按验收清单确认 |

## 能力缺口与后续接口

下列能力仍需要 Nons 补齐稳定本地接口后，AF 才能提供真实入口；当前只保留能力位，不提供无效 UI：

| AF 需求 | Nons 需要提供 |
|---|---|
| 歌单浏览 | 当前来源/账号下的歌单摘要、稳定歌单引用、名称、封面、数量、排序和分页 |
| 歌单歌曲 | 歌曲引用、标题/歌手/专辑/时长/封面、分页游标、总数、歌单版本 |
| 播放整个歌单 | 歌单引用、本次排除项、可选起播歌曲、浏览时版本；校验失败保留原队列 |
| 队列来源 | 可确认的队列来源歌单引用；不能用正在浏览的页面推断 |
| 队列编辑 | 队列条目稳定 ID、移除、下一首播放命令 |
| 收藏 | 当前歌曲收藏状态、可修改性、账号隔离、实际结果 |
| 页面导航 | 唤醒 Nons 并打开指定歌单，仅导航 |
| 上下文与关联 | 账号/来源不透明上下文及变化事件；请求 ID 和逐请求结果 |

## 验收

自动检查覆盖开放 API JSON/命令字段、事件归并和队列版本冲突、错误码映射、队列投影、布局默认值和浮层 XAML 加载。串行构建、测试、设置契约格式检查和 `git diff --check` 通过只证明这些局部行为。

真实 Windows 验收需要覆盖：真实 Nons 队列打开、当前项标记并居中、重新打开后选中/播放标记保持、单击跳转、中键回到当前、固定五行、低清封面和有界缓存、滚动条留白、驻留默认关闭与悬停默认开启、来源切到不支持播放器时两处入口隐藏、完整面板随机开/关、Nons 切歌/修改队列/重启、关闭开放 API、主题/高对比度、96%/125%/150% DPI、多显示器、Explorer 重启和 AF 退出。未执行的环境或场景记为“待维护者验收”，不能以构建、截图或短时启动代替。
