# 按模式组织设置页

当前实现为第一阶段：页面组合、呈现上下文与配置访问边界。运行宿主仍只有任务栏，设置文件仍使用现有 schema，原有字段与枚举序列化值保持兼容。显示器、横竖方向与未来模式的配置隔离尚未实现。

## 职责与入口

| 入口 | 职责与所有权 |
| --- | --- |
| `ISettingsEnvironmentReader` / `SettingsEnvironmentReader` | 在后台读取领域服务提供的显示器与任务栏矩形、DPI；快照包含实际运行模式、目标显示器、实际朝向与紧凑状态。不持有 HWND，不写运行目标或朝向。 |
| `SettingsContextService` | 每个设置窗口一个会话，定时刷新快照。默认选择已启用目标中的主屏，主屏未启用则选择首个有效目标；选择器只改变编辑目标，显示器断开后回退。关闭时取消查询并拒绝迟到结果。 |
| `SettingsPageCatalog` | 声明稳定页面键、模式可用性、导航文案、图标及全局/模式所有权，不引用具体 View。 |
| `SettingsPageProvider` | 视图层把页面键解析成具体 Page 类型，实现 WPF-UI 页面解析入口。 |
| `SettingsPageScopeCache` / `SettingsPageContext` | 每个缓存页面拥有独立 DI 作用域；模式页面按模式、显示器、朝向、紧凑状态和环境可用性缓存。离开上下文先取消其异步工作、禁止旧编辑写入，重返时刷新缓存的可绑定状态。全局页面按页面键缓存。关闭窗口释放所有作用域与订阅。 |
| `ISettingsConfiguration` / `LegacySettingsConfiguration` | 页面读写入口，集中保留现有规范化、通知和重置路径；`HasIndependentProfiles` 当前为 `false`。此适配器的旧设置源仍共享，缓存隔离不能当作数据隔离。 |

DI 注册统一位于 `App.xaml.cs`。窗口拥有会话作用域，缓存拥有子作用域，服务与 ViewModel 不负责创建具体视图。显示与位置、内容与布局、歌词及交互跟随任务栏环境。统一外观页保留全局页面和字体编辑器，以另一上下文作用域提供媒体栏编辑器；切换环境只取消并替换后者。应用、媒体与通知、更新亮点及关于保持全局缓存。

## 页面职责

- 显示与位置：实际运行模式、运行目标列表、位置、避让与锁定；未实现模式收起为说明，不激活宿主。窗口顶部的显示器选择只改变编辑环境，不能代替运行目标列表。
- 内容与布局：常驻内容及无媒体保留项、文字布局、整体和歌词区域长度、间距、快捷控制及完整面板。`ContentLayoutViewModel` 组合同一上下文的既有编辑器；组件参数仍由 `ComponentsSettingsViewModel` 管理。竖向环境隐藏横向排列和排序操作，保留歌词对齐。
- 外观：全局主题、强调色、窗口材质及通用字体，与媒体栏专属字号、颜色和磨砂背景分组呈现。字体查询仍在后台，离开页面或关闭窗口会取消，迟到结果不能写回已释放的 ViewModel。
- 歌词：启用、单双行与第二行优先级、擦亮、文本处理及取词。布局和长度通过稳定分组入口跳转，不重复编辑。
- 交互、媒体与通知、应用：分别负责输入映射，媒体来源/快速启动/曲目通知，以及语言/启动/更新/配置/诊断。更新亮点与关于保留页脚入口。

任务栏文字色和背景层通过 `SetTaskbarAppearance` 更新，只有活动任务栏上下文可以写入；全局外观的写入与重置保留这些字段。外观重置不改变布局，内容与布局重置包含各层显隐、组件顺序与参数及歌词对齐和长度；歌词重置保留这些已移出的字段。显示与位置重置只恢复该页字段。所有重置使用用户默认快照，一次性 TranslucentTB 兼容提示不随重置重新触发。

应用主题与字体、语言、启动和更新仍为全局设置。当前任务栏各显示器与横竖方向共用原有配置，该限制不影响编辑目标选择；模式配置隔离留待后续发布批次。

## 导航、搜索与环境变化

导航集合由页面目录生成，当前有七个主设置页和两个页脚入口。搜索按当前上下文过滤模式页面及全局分组，目标为稳定的 `SettingsPageKey` + `SettingsGroup.GroupId`。旧显示模式、应用外观、歌词对齐及布局分组入口通过目录映射到现有编辑位置；重组不改序列化字段或枚举值。搜索会展开目标分组的详情，然后定位与强调。

上下文切换先提交当前数值草稿并完成焦点编辑，再取消旧上下文工作。页面仍适用时保留当前页面键，只替换受环境影响的内容；全局页面不会因显示器或朝向变化重建。页面提供器关闭 WPF-UI 自身的页面缓存，由作用域缓存统一管理身份，避免导航再次取回旧上下文页面。

## 后续顺序

1. 在单独发布批次实现五份配置：任务栏横向、任务栏竖向、灵动岛、桌面卡片、悬浮球。共享歌词实现绑定各自实例；紧凑状态不新增配置。迁移保留旧数据，以当前任务栏值初始化横竖配置；定义默认值与按页面、按模式、全部重置的范围并测试互不覆盖。
2. 每个任务栏宿主按自身显示器的环境选择配置，混合横竖不使用单一全局朝向；紧凑任务栏只执行外观适配策略。
3. 新模式先实现宿主，再加入目录、配置适配器和页面组合。布局/职责相同的页面复用；差异显著的外观、组件与交互页面使用独立 Page 和 ViewModel，不在共享大页面中堆积模式判断。
4. 由业务服务协调运行模式切换、取消与资源释放。设置页只发送切换意图；切换成功才发布新运行上下文，失败保留原宿主并明确反馈。

## 验证边界

自动检查覆盖主屏默认、显示器断开回退、编辑选择不改环境、未实现页面守卫、稳定搜索目标、上下文缓存隔离与复用、取消和释放后拒绝迟到结果；WPF 测试加载编译页面、真实导航控件及横竖内容，验证运行时字面量和提供器缓存行为。

上述检查不代表实际任务栏宿主验收。启动与退出、多屏混合朝向、DPI、Explorer 恢复以及系统紧凑状态的实机表现仍须维护者在真实 Windows 环境验收；未来模式切换与配置迁移须在对应实施批次增加验收。
