# AF Media Bar 测试制定规范

> 本文用于 AF Media Bar 的测试选择、编写与审查；构建命令见 [贡献指南](../CONTRIBUTING.md)，实机场景按受影响的功能文档执行。

AF Media Bar 是 Windows/WPF 桌面应用，优先防止错媒体、歌词错误、布局异常、设置丢失、UI 卡顿和退出后资源残留。测试应足够好，而不是数量多；AI 生成的测试也要考虑编写、维护、运行和误报成本。

## 价值判断

> 测试价值 = 捕获真实缺陷的概率 × 缺陷影响 × 长期复用价值
> − 编写成本 − 维护成本 − 运行成本 − 脆弱与误报成本

先确认要防止什么用户问题、已有测试是否覆盖，再选择成本合适的验证方式。覆盖率只作参考，不作为目标；没有新增价值时不补测试，但仍执行改动要求的已有检查。

## 现有验证基础

- [MSTest 项目](../tests/AFMediaBar.Layout.Tests/AFMediaBar.Layout.Tests.csproj) 位于 `tests/AFMediaBar.Layout.Tests/`，使用 Windows/WPF 环境。已有歌词解析与缓存、部分 XAML 资源、封面主色、剪枝、材质回退、日志、设置快照和安装准备回归；项目名称不代表所有布局策略已有覆盖。
- [构建 CI](../.github/workflows/build.yml) 执行还原、Release 构建、测试、单文件发布和安装包产物检查，并验证发布数据与贡献者名单脚本。它没有完整桌面启动、菜单退出、播放器或真实安装验收。
- [架构检查](../tools/verify-architecture.ps1) 用于 ViewModel 等代码边界；[歌词布局检查](../tools/verify-lyrics-layout.cjs) 使用 Playwright 与 Edge 验证内嵌网页，不能替代 WebView2 宿主验收。均按实际改动选择，运行条件须满足。

覆盖以当前测试源码为准，不根据文件名或历史通过记录推断。已有测试能防止本次回归时直接复用；不能覆盖时，再补最小的有效验证。

## 按模块选择测试

下表是改动时的候选风险，不要求一次补齐全部测试，也不表示已有覆盖：

| 模块 | 优先验证的行为 | 适合的自动验证 |
|---|---|---|
| 媒体与通知 | 来源过滤、会话切换、过期快照、首次快照不通知、同一曲目不重复通知 | 本地媒体快照与既有选择、通知策略；不连接真实播放器 |
| 歌词 | 损坏或混合格式、时间轴与译文、匹配、缓存失效和重复请求 | 本地歌词文本与可控的提供器结果；不依赖在线取词 |
| 任务栏与封面 | DPI 换算、多屏坐标、可用宽度、无效尺寸、横竖封面比例与透明主色 | 几何计算、`ArtworkBoxPolicy`、内存位图；尺寸结果不能证明界面未裁切 |
| 设置与持久化 | 旧 JSON、无效值回退、重置范围、用户默认快照、失败写入不丢数据 | 真实序列化与独立临时文件；不改 schema 或用户配置 |
| 异步与生命周期 | 取消后不发布、旧结果丢弃、重复停止与释放、计时器自停、UI 保持响应 | 可控同步信号与必要的 STA/Dispatcher 测试；不只断言调用次数 |
| 音频与输入 | 设备选择、延迟操作只应用最新结果、音量边界、滚轮目标判断 | 既有音频与输入策略、必要的外部适配器替身；不改变实际音量或发送全局输入 |
| 材质与日志 | 必要原生调用失败后回退不透明背景；满队列保留新 Error、持续入队仍落盘 | 注入原生失败、必要的 WPF 检查；独立临时日志与有界并发 |
| 更新与安装 | 哈希不符、越界路径、旧版本、取消、文件被替换、重复安装与退出交接 | 真实临时安装包与文件读写，只替换安装环境判断和进程启动；不运行真实安装程序 |

正常路径提供对照，边界与失败分支用于防止实际错误；不要为每个枚举、尺寸或播放器排列全部组合。配置字段、枚举值、来源身份和更新数据格式属于兼容要求，改变相关行为时验证旧数据，不测试每个属性的读写。

## 编写与隔离

1. 先读已有测试、相关入口和功能规则，说明未覆盖的用户风险。修复 bug 时，优先选择修复前失败、修复后通过的回归；无法自动复现时记录替代验证与剩余风险。
2. 每个测试验证一个清楚的行为，名称说明条件与结果。优先既有纯策略和真实对象，只替换网络、COM、原生调用或进程等必要的外部依赖；不把待验证的解析、哈希或文件写入替换为固定成功。
3. WPF 测试按需复用 [StaTest](../tests/AFMediaBar.Layout.Tests/StaTest.cs)，在所属线程操作对象，结束时关闭窗口与 Dispatcher。修改 `SettingsManager`、静态缓存或共享资源时禁止并行，并在 `finally` 或清理方法中恢复原状态。
4. 文件测试使用独立临时目录，关闭句柄后清理。异步测试优先用同步信号等待条件，设置超时并观察异常；避免依赖固定长延时、精确耗时或无限循环，结束时取消并等待自己启动的任务。

优先测试公开行为，不为测试一处简单逻辑新增服务、接口或大范围重构。现有部分回归使用反射控制状态，应限制在必要的准备与观察中；不要把私有字段名、第三方对象内部结构或固定调用顺序当作测试目标，也不要为消除旧反射顺手重写整套测试。

## 通常不添加

- 简单 getter/setter、常量、默认值列表、纯委托和生成代码；设置默认值涉及兼容或已有缺陷时才针对具体行为验证。
- 私有实现、重复正常路径、第三方库自身行为、过度 mock，以及无有效断言的覆盖率测试。
- 精确动画帧、字体像素、控件排列、整页截图或日志原文；稳定复现实际缺陷的局部检查可保留，不能代替交互验收。
- 为测试歌词而连接所有在线提供器，为测试媒体而启动所有播放器，或把全部桌面操作加入端到端流程。

审查 AI 生成或已有测试时，确认失败代表实际问题、行为不变的重构仍能通过、结果稳定且易定位、没有重复覆盖、维护成本合理。低价值测试可合并或删除，但须说明失去的覆盖与替代验证，不能机械地顺手删测试。

## 自动检查与实机边界

代码改动按贡献指南串行执行还原、Release 构建、测试和差异检查，避免 WPF 生成文件竞争；修改 ViewModel 补架构检查，修改 XAML 核对资源、绑定及运行时字面量。现有 XAML 测试只覆盖部分页面，不代表全仓库已检查。

任务栏定位与自动隐藏、多屏/DPI、Explorer 恢复、SMTC 与播放器、Core Audio、Hook、Popup、锁屏与睡眠恢复、正常退出清理，以及真实安装和 UAC，均按受影响场景做 Windows 实机验收。封面显示改动检查任务栏、完整面板与通知的横竖封面及无封面切换；原生材质改动检查支持系统上的成功与回退。

只验证改动可能影响、项目声明支持的系统与播放器。普通逻辑改动不要求跑全矩阵、完整桌面端到端或发布流程；安装分发改动再补打包与安装检查。构建、产物存在、截图或短时启动不能写成实机通过，缺少环境时标明“待维护者验收”。

纯文档修改只检查差异、链接、规则一致性和编码，不新增测试，也不要求构建或启动应用。
